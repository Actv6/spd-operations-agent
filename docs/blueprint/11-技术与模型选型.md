# 11 · 技术与模型选型

更新：2026-09-27。用户明确要求先用 DeepSeek，key 稍后提供。本文覆盖原 Qwen 主选；这是设计选型与开发授权，尚无真实账号调用和兼容性通过证据。当前实施范围见 [M1 开发交接](13-M1开发交接.md)。

## 1. 当前主选

| 部分 | 选择 | 边界 |
|---|---|---|
| Agent 框架 | Python LangGraph | 一个受控 Agent，显式状态、白名单工具、工具次数/超时预算 |
| 生成模型 | DeepSeek 官方 API；默认 `deepseek-flash`，配置可改 | 用户指定供应商；账号可见型号和真实能力待 key 后实测 |
| RAG 服务 | 自建轻量知识模块 | 版本、ACL、生效范围、分块、引用；M1 真实词法检索先行 |
| Embedding | 可选 `text-embedding-v4` 1024 维 | 独立供应商配置，不随 DeepSeek key 自动可用；不阻塞 M1 |
| 向量库 | PostgreSQL + pgvector 扩展 | 准备存储/迁移；真实 Embedding 接入后验证精确向量检索与混合检索 |
| 检索 | M1 中文词法检索；后续词法+向量 RRF | 授权与有效版本过滤先于召回；返回实际 retrieval_mode |
| Reranker | M1 关闭 | 以后经消融证明收益再引入 |
| 后端 | FastAPI / Pydantic，模块化单体 | 一个 API + 一个同仓库 worker，数据库持久任务 |
| 数据 | PostgreSQL / SQLAlchemy / Alembic | 账号、会话、权限、业务事实、运行和知识元数据由后端保存 |
| 前端 | React / TypeScript | 第三种 UI；只调用项目 API，不直接访问模型 |
| 目标部署 | 腾讯云 Docker Compose + Nginx | 2 核 / 2GB / 50GB，不在本机推理大模型；本轮不云部署 |

LangGraph 用于受控流程和持久状态，不替代领域规则与事务。不强制再装 LangChain 高层 Agent、LlamaIndex、Dify/RAGFlow、Milvus、Elasticsearch 或 Redis。[LangGraph 概览](https://docs.langchain.com/oss/python/langgraph/overview)、[人工中断](https://docs.langchain.com/oss/python/langgraph/interrupts)

## 2. DeepSeek 配置和验证

- `DEEPSEEK_BASE_URL=https://api.deepseek.com`，`DEEPSEEK_MODEL=deepseek-flash`，`DEEPSEEK_API_KEY` 仅在服务端注入。
- 官方当前 `/models` 样例将 `deepseek-flash` 显示为 DeepSeek-V4.1-Flash；别名可变化，不能宣称固定快照。拿到 key 后核实账号型号，运行记录请求模型、响应模型、接口配置、usage，以及供应商实际返回的版本信息。没有返回精确版本时如实记录未知。[模型列表](https://api-docs.deepseek.com/api/list-models/)、[更新记录](https://api-docs.deepseek.com/updates/)
- 先显式非思考模式。工具调用由后端实际执行白名单函数、关联 tool_call_id，再返回结果；不让模型直接执行 SQL、网络任意请求或库存写入。[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)
- 最终输出先采用 JSON Output + Pydantic 和证据校验。不要沿用原 Qwen 专用参数；DeepSeek strict 工具 Schema 为单独兼容点，不假定普通端点支持所有严格约束。[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[Chat API](https://api-docs.deepseek.com/api/create-chat-completion/)
- 后续若启用思考模式，要按供应商协议保留必要的工具轮次字段；前端只展示运行摘要和工具证据，不暴露原始推理过程。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)

Provider Adapter 负责字段转换、Schema 子集、tool call ID、超时/取消、错误、usage 与版本记录。领域和前端不依赖厂商 SDK。缺 key 时真实 provider 明确报配置未就绪；离线测试显式选择 mock provider，不能静默伪装模型成功。

## 3. RAG 的分阶段方案

M1 使用现有模拟 Markdown/纯文本，实际实现解析、分块、发布版本、生效范围、项目授权过滤、中文词法召回及可回查引用。没有模型 key 时可分别验证真实检索和 mock 生成；拿到 DeepSeek key 后，词法检索也能组成真实检索增强生成，不必等待第二家账号。

知识库不是仅存向量。每个片段需带文档版本、章节、来源 hash、项目、生效区间与 synthetic 标签；无权和失效内容不进入召回候选，引用必须指向此次实际提供给模型的证据。

后续 Embedding 主选保留 `text-embedding-v4` 1024 维作为起点，单独配置 API key 和地域。query/document 模型与维度保持一致；用 pgvector 精确检索建立小语料基线，词法/向量各取 20 条，RRF 后最多 6 条作为待评测参数。无 Embedding 时不造随机向量、不声称语义检索已通过。[Embedding 接口](https://www.alibabacloud.com/help/en/model-studio/text-embedding-synchronous-api)、[pgvector](https://github.com/pgvector/pgvector)

## 4. 成本、可维护性与验收

本次不沿用 Qwen 的价格计算 DeepSeek 成本，也不在无 usage 情况下宣称每次或每月费用。真实调用后记录输入/输出 token、请求数、重试、延迟和当时账号计价；批量付费评测前明确预算。M1 的本地 mock 测试不计入真实 LLM 成功率。

先锁定实际运行的 Python/Node、LangGraph/checkpointer、SDK、数据库与前端依赖。20 个小案例可检查工具参数、中文结构化输出、空/截断响应、限流、超时、缺依据和引用，但不等于业务效果证明。QA 分开记录注册登录、RAG 检索、mock Agent、真实模型、向量检索、浏览器与部署。

后续模型切换需要记录 ADR、同例回归和数据发送范围，不因失败自动把资料发往另一家供应商。千问/豆包保留为历史研究候选，本轮不同时开发三家 adapter。Embedding 更换需重建索引并验证，不能只替换字符串。
