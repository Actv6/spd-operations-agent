# 07 · 评测与验收

状态：测试计划与拟定门槛，**尚未执行目标后端或真实 AI 评测**。已有前端 18 项检查不计入这里的通过率。

## 1. 测试分层与责任

| 层 | 执行/审阅 | 核查重点 | 证据 |
|---|---|---|---|
| 需求与契约 | QA 提前参与，PM/TL 复核 | 术语、空/失败状态、权限、接口消费者是否一致 | 用例、契约差异、评审结论 |
| 规则/数据单元 | BE 自测，QA 独立预期 | 单位、日界、冻结/预留、缺日、在途、批次 | 输入、精确预期、规则版本、测试日志 |
| 服务/数据库集成 | BE/QA | 项目隔离、事务、乐观锁、队列租约、幂等 | 数据库状态和请求记录 |
| 工具/模型协议 | AI 自测，QA 复核 | 工具参数、结果关联、Schema、重试、usage | 脱敏请求、模型 ID、结构化输出与判定 |
| RAG | AI + QA 标注 | 适用资料召回、引用、旧版和越权过滤 | 检索结果、gold evidence、逐条评分 |
| Agent 端到端 | QA 独立案例 | 问题→工具→证据→草稿→批准→任务 | trace、事件序列、最终业务记录 |
| UI/发布 | FE/QA/OPS | 交互、键盘、异步、失败恢复、资源与备份 | 浏览器证据、部署日志、恢复演练 |

开发者提交自测之后，QA 执行自己的预期而不是复制实现里的答案。由同一助手完成的测试也必须标明身份边界，不能伪造独立业务人员的认可。

## 2. 数据集规划

已有 G01–G14 只是一组种子：G01–G09/G11 涵盖库存与计算边界，G10 跨医院，G12 版本，G13 无依据，G14 文档注入。现有标签写着 not_executed_against_agent，必须保留到真实运行后才能更新状态。

拟扩展 120 个案例：40 个规则/质量、30 个检索/引用、30 个 Agent 行动/澄清、20 个权限/恢复/故障。数量是目标，不是已生成。按场景模板和文档来源分成开发集 80、保留集 40；相近改写不能分到两边假装独立样本。

保留集由 QA 维护，开发者先拿类型与判分标准，不拿可直接写进提示词的答案。每例包含问题、身份、快照/资料版本、允许工具、必须/禁止行动、关键指标、支持证据和预期状态；没有唯一工具顺序时按约束评分，不强求某条执行轨迹。

## 3. 模型比较与消融

主选改为 DeepSeek。后续进行候选对照时使用同一数据、工具、token 上限和预算；M1 不强制额外采购候选模型。先以 20 例 G2 检查兼容，再做完整验收；性能测试使用真实调用，mock 不能顶替。

同案例比较 A 规则+模板、B 规则+固定 RAG、C 规则+RAG+受限 Agent。看 C 是否改善补查、澄清、证据组织和行动可用性，也报告新增成本和耗时。不把 C 的规则 fallback 算成模型成功。

对保留集关键 AI 案例重复 3 次，保留全部结果；记录样本数、每次/聚合通过率及最差结果，不只展示最好一轮。LLM judge 可辅助分类，关键数字、权限、写入结果用程序验；引用语义与业务可用性要有人复核。

## 4. 指标与拟定发布门槛

| 指标 | 定义 | 初始门槛（待评审） |
|---|---|---|
| 确定性正确 | 满足精确指标/单位/日期预期的规则例数 ÷ 执行规则例数 | 测试集中 100% |
| 授权/行动硬约束 | 越权读取、无批准写入、重复任务、取消后提交的违规数 | 0 次；任一发生阻断 |
| 引用可定位 | ID、来源版本、位置与哈希有效的引用 ÷ 全部引用 | 100% |
| 检索 Hit@6 | 有答案查询中至少一个 gold 片段进入最终 6 条的比例 | ≥95%；另报多证据完整召回，不能混称 |
| 引用支持度 | 被所引证据支持的可验证 claim ÷ 被审阅 claim | ≥95%；关键错误单列阻断 |
| 不足/冲突处理 | 正确标明不足或冲突且未编造结论的例数 ÷ 相应例数 | ≥95%；越权/未经批准处置仍为 0 容忍 |
| 工具参数成功 | 首次通过 Schema、授权和业务参数验证的调用 ÷ 全部工具调用 | ≥95%；最终结果仍须过 validator |
| 模型端到端成功 | 没用 fallback 且完成预期分析约束的运行 ÷ 应使用模型的运行 | ≥90%，单列超时、语义错、格式错 |
| 成本/延迟 | 每个运行总费用、tokens、请求数、端到端 p50/p95 | G2 后据实定上限；现在不伪造 SLA |

比例必须同时显示分子/分母和样本限制，小样本 100% 不代表真实世界零错误。发布门槛是本项目拟定标准，不是模型厂商承诺或行业认证。

## 5. 必须覆盖的故障与交互

- 在途按时到货应避免简单库存天数误报；日期/同日到货含义明确。
- 旧快照、缺两天消耗、零消耗、未知单位/交期分别处理，不能都变成零或充足。
- 同产品编码跨项目、撤销成员权限、被停用制度、恶意片段不能泄漏/授权。
- 草稿编辑与批准并发、批准后证据变化、两个批准请求、写任务后 worker 崩溃均不能重复/错执行。
- 工具成功空结果与 TIMEOUT 不同；模型 429、截断 JSON、错误引用、预算用尽均有可见结果。
- 页面断网/刷新恢复、迟到事件、取消、已完成/拒绝/冲突、重开任务、键盘与窄屏均有用例。
- 2GB 环境记录空闲/峰值内存、数据库和 worker 同时负载、日志/磁盘增长、进程重启恢复，不只看容器启动。

## 6. 报告、缺陷与退出

报告必含版本组合（代码/契约/规则/提示词/模型/索引）、数据集 hash、环境、执行时间、样本数、模型与 fallback 分栏、失败明细、复现方法和未测项。没有日志和输出不填写通过。

P0：泄漏、越权、不可恢复数据损坏；P1：核心流程/数值错误、无审批行动、幂等失效；P2：有替代路径的交互/性能问题；P3：不影响关键行为的样式问题。P0/P1 不得带入试点；P2 必须逐项解释并取得范围内接受，不能用“测试通过”掩盖。

退出分三层：合成数据工程验收；获准脱敏案例盲测/影子运行；公司业务负责人有限试点验收。前一层通过不代表后一层通过。
