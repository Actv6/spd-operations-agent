## 这份底稿解决什么

为国控广东生物科技相关的医院 SPD 运营场景设计一个能查数据、找依据、提出行动并接受人工控制的 Agent。当前没有内部访谈、内部数据、真实 SOP 或公司授权接入系统，因此业务流程和阈值都是待验证设计，不代表公司现行制度。

用户已明确：先完成产品、架构、功能和交互设计，再开始开发；项目重点是 AI 技术与后期可维护性。第三种 UI 只代表风格选择。此前提前制作的 `frontend/` 保留为交互草稿，不作为功能规格或生产架构的依据。

## 核心设计

产品主路径：提出运营问题 → 校验数据 → 调用工具核查 → 检索适用制度 → 展示结论与证据 → 人工审阅草稿 → 创建内部任务 → 记录处理反馈。

AI 负责语义理解、在白名单中选择查询工具、基于证据作解释和提出核查动作。代码负责数量、日期、权限、版本、事务与业务状态。人负责确认行动与业务处置。三者有明确输入输出，不能互相替代。

初版一个 Agent，LangGraph 编排；FastAPI 模块化单体；PostgreSQL + pgvector；React 前端。生成模型按最新用户指令改为 DeepSeek；M1 先实现真实词法检索、引用及显式 mock 生成，key 后补真实生成验证。Embedding 和 pgvector 接口保留，需独立配置后验证。详见 11/13；本稿不冒充已测技术栈。
