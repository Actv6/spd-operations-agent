# 人工复核闭环实施基线

2026-10-05。用户以“对的，开始补”授权上一条建议的本地实施。作者、实现与自检：当前 Codex；不宣称独立业务签收。

## 契约与范围（实施前记录）

沿用核查详情和核查记录，不新增菜单、邀请或角色管理。现有 owner/demo_owner 可提交人工复核，现有项目成员可读；服务器确定身份。本人核查须显示“本人自查”，其他有权限账号显示“其他账号复核”，不将不同账号等同专业资格认证。

新增 GET/POST /api/v1/runs/{run_id}/human-review：初始 pending，追加 confirmed/error/insufficient/pending 记录；必须填写结论与核查依据，错误/不足须说明下一步；同运行来源可关联 evidence_ids，外部依据是人工记录、非系统验证。记录保存身份、时间、快照、分析hash、来源token和已处理反馈ID，不覆盖分析、证据、反馈或历史复核。POST 使用幂等键、revision和source_token，项目锁串行化复核、反馈、发布和待办确认。

高关注、数据质量问题、依据不足、工具未覆盖/旧质量契约及业务待办需要人工复核。普通无命中结果仍保持“待人工复核”，允许人工抽查，不声称已获人工认可。新“需要修正”反馈使结果重新有争议；复核须明确处理全部待处理纠错反馈。

待办确认前检查当前核查与会话祖先：争议/资料不足、必要复核未确认、来源已失效阻止确认。已创建任务不自动取消，详情提示需要再次核实；任务完成不消除异常。确认本人内部待办不等于业务审批。

失败/取消运行可记录“人工核查结论”，不改AI运行状态，不伪造模型成功；仍可查看绑定库存和运行中已经保存的依据。模型运行中不能提交复核。本轮不新增独立脱离运行的人工工单。

数据库新增 human_review_states 与 human_review_records，Alembic仅在隔离库验证，不切换日常服务或日常库。OpenAPI增加可选人工复核摘要及待办阻断信息，API v1.3；旧历史初始待人工复核，不回填通过。新数据或制度可使用现有人工维护功能修正后重新核查，无自动重跑或库存写回。

## 验证设计

先定义后端用例：原文/hash保真、必填、失败人工处理、权限/撤销权限、他人/本人身份、异源依据、反馈重开与确认阻断、父会话阻断、失效/来源token、revision/幂等/并发、普通结果抽查及任务完成不消除异常。前端验证状态、失败流程、证据入口、反馈处理、待办阻断、窄屏与刷新恢复。完整本地回归与迁移检查保存日志；原停止付费轮次不续跑，无付费调用或云上传。
