## 结论

已执行 [V1.1计划](V1.1可靠性与试用准备计划.md) 的本地实现与验证范围，API v1.1、迁移 v1101、提示版本 v11-quality-1。当前本地入口为 http://127.0.0.1:4180。真实模型复测、业务人员评审、生产PostgreSQL与云部署仍未完成，不解除此前业务试点质量门槛。

## 实际交付

1. **回答可靠性**：新运行从本轮风险工具事实保存高/中关注数量与完整清单，在结果页直接显示；旧记录缺字段时不回填、不重写。校验支持共/共有/合计、中文数字、全角、Markdown与倒装计数，保留一次纠正后持续错误判失败；增加词法检索不能证明“知识库不存在”的表述检查。自然语言校验仍是有限规则，不证明每句事实正确或引用蕴含。
2. **离线评测**：新增独立可运行脚本与开发挑战集，无provider调用、不读取日常数据库。11项回答校验通过；7项检索检查6项通过，口语“有几天的用量没填咋办”漏召回，原样保留。作者自建数据不是独立盲测，不能作为总体召回率或模型准确率。
3. **反馈闭环**：结果页可提交“有帮助/需要修正”，需修正必须说明原因；本人反馈可回读。反馈追加保存，关联原答案hash、运行/快照、规则/模型/提示/知识版本；接口校验现时权限和幂等。反馈不会训练模型、改写历史或自动建任务。
4. **知识维护**：现有知识库内增加维护页签，支持粘贴或读取md/txt正文（最多50,000字符，文件最多200KB）、预览、人工发布新版本、停用和最近100条变更回查。项目所有者维护；同名有效版本冲突与同版本覆盖拒绝，旧目录或正文预览拒绝发布。停用不删除正文和证据。发布即当天生效，暂不支持预约生效、PDF/Word解析和多人审核流。
5. **试用准备**：完成 [业务评审与真实复测方案](V1.1业务评审与真实复测方案.md)，包含12类评审案例、耗时/采纳/修订记录模板和下一轮真实模型预算提案。没有冒充已邀请业务人员、已获预算或已完成盲测。

## 复现

从项目根目录执行：

```sh
cd backend
.venv/bin/python -m pytest -q
.venv/bin/python scripts/evaluate_v11_offline.py --output ../docs/verification/v11-20261001/offline-challenge-rerun.json
```

第二条命令目前因已知口语漏召回返回1，这是刻意保留的评测失败，不是执行错误。不会请求模型。前端按 frontend/package.json 执行 typecheck、check:api、test:ui、test:sites 和 build。运行前使用本机可用的Node路径。

浏览器fixture脚本为 backend/scripts/serve_v11_browser_fixture.py，强制新数据库、不加载.env、DeepSeek密钥为空、只有受控provider播种历史。浏览器验收脚本 v11-20261001/browser-check.mjs 使用本机路径与临时测试会话；跨机器复现需重新建立fixture、登录会话并调整Chromium路径，不能直接复用日常账号。

## 未完成和限制

- 未新增付费DeepSeek调用，当前提示版本没有新的真实模型通过结论；历史六例的问题不能因离线测试通过就宣称全部解决。
- 口语检索漏召回仍存在；尚未接入embedding、混合检索或reranker，应依据更广泛问题集再决定。
- 反馈已采集、可回读并关联版本，但还没有反馈运营看板、自动归因或训练流程。
- 资料更新采用“停用旧版→预览并发布新版”，两步之间有知识暂缺窗口；不具备原子替换/预约发布/多人审批。需要时另行设计共享契约。
- 数字和绝对化措辞检测不是通用语义证明；需业务人员逐句核对事实与引用支持。当前正文长度和限定追问服从仍主要依赖提示词，须真实模型验收。
- 团队分派、企业数据接入、生产监控/告警、费用对账、生产部署继续保持后续范围。
