# M2 本地开发基线 · 2026-09-28

用户已批准：异常中心、多轮追问、批次/14日消耗工具、本人待办闭环。实施/验证执行者为当前 Codex；没有独立 QA 或业务验收。沿用当前紧凑布局；不扩展跨人协作、采购执行、库存写入或部署。

## CR-M2-001（实现前记录）

- RunRequest.mode 扩展 analyze/follow_up/draft_action；后两者必须关联本人成功父运行，服务端固定原项目、快照和范围，沿用 session_id。禁止客户端改写继承范围；最多12层，提供最近6轮文本上下文，事实重新查工具。原 analyze 兼容；明确返回 parent_run_id/context。
- 只读工具新增 get_batches/get_consumption/compute_risks；全部由服务端收窄物资与科室。14天窗口以快照时点计算，缺失不补零。异常由确定性代码遍历全范围，返回覆盖计数、规则版本、阈值和跳过估算对象。低覆盖7天、临期30天为本地核查阈值，不是企业已批准制度。
- 新增项目 /risks、/item-details、/tasks、运行 /conversation、草稿读取/确认/拒绝、任务更新 API。金额/数量继续为 Decimal 字符串。
- draft_action 仍是异步模型运行，最终输出带结构化任务草稿；不自动建任务。草稿关联分析、快照、原文证据和创建人。确认时提交精确编辑内容及 revision，重检项目权限、快照和知识有效性，唯一 draft_id 防重复；相同重复确认返回同一任务，内容变化返回冲突。
- 任务仅本人可见/处理；待处理→处理中→已完成，允许取消与重开。完成必须填写结果；带版本比较与操作记录。任务完成不改变异常状态，异常仍从快照计算。
- 前端共用 PageHeader/DataTable，增加异常/本人任务入口，结果中连续追问/生成草稿，库存支持明细。保留旧API、历史分析和/prototype。

## 实现前测试设计

1. 风险全量覆盖、7/30天边界、过期与冻结、缺日不估算、相同快照确定性。
2. 批次/消耗实际源记录与缺失日期，工具拒绝额外参数、跨范围与跨项目。
3. 追问继承项目/快照/科室，父运行失败/他人/跨项目/冲突字段拒绝；历史上下文有限且不充当新证据。
4. 模型草稿严格校验、无证据不能产出行动、无key明确失败；未确认任务数为0。
5. 确认重试幂等、编辑内容精确保存、不同重复内容冲突、旧revision冲突、证据过期/快照更新阻止确认。
6. 本人任务权限、非法状态迁移、完成必填、重开和取消留痕；完成不消除风险。
7. 既有后端回归、迁移无漂移、OpenAPI类型、前端构建；浏览器异常→核查→追问→草稿确认→任务完成/重开、历史刷新和窄屏。
8. 真实DeepSeek验证单列；固定测试provider不计真实模型成功。不声明部署、真实企业适用性或向量检索通过。

实现修订：真实草稿模型尝试一次查询5种只读工具，原4次预算拒绝并保留失败记录。M2 默认工具预算提高到8次（配置上限仍8），总运行45秒与图递归20步保留，每轮明确剩余预算；测试夹具固定4次继续验证旧预算反例。失败重试保持模式/父运行/范围/快照，采用新的幂等键。

费用留痕修订：模型返回后先记录本轮 usage，再校验工具调用预算，避免未来预算拒绝遗漏已消耗用量。初次真实预算失败发生在该修订之前，历史缺失用量保持未知，不补造。

真实全项目分析发现生成内容存在非法JSON换行，严格拒绝而未保存分析。新增至多一次模型格式纠正，仍受45秒总时限控制；不使用字符串拼接或宽松解析伪造成功，原调用与纠正调用均留存usage。

全项目真实样本暴露语义问题：3项不能估算中含1项零消耗，模型曾统称为数据质量问题。工具与RiskReport补充 estimate_gap_counts（数据质量/零消耗分别统计），异常页绑定服务端原因计数；不把该历史回答当作语义全对，亦不声称已经自动逐句验证。
