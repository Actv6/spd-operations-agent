# M3.1 物资档案与科室目录

2026-09-28；实现/自检：Codex，非独立QA或正式上线验收。基线：[M3.1接口与验收基线](M3.1接口与验收基线.md)。

## 已交付

新增菜单“物资档案”（/app/products）和“科室目录”（/app/departments）。支持搜索、状态筛选、分页、新增、编辑、停用与重新启用；编辑抽屉展示修改记录。复用共享DataTable与紧凑台账，短桌面窗口侧栏可滚动，移动端抽屉正常布局。

物资：编码、名称、规格、基础单位、状态。科室：编码、唯一名称、状态。编码统一大写，项目及类型内唯一，停用记录继续占用编码；科室名规范化后唯一。名称/单位拒绝空白及公式前缀，字段拒绝控制字符，并检查Unicode规范化后的长度。

owner/demo_owner可维护，其他成员只读，跨项目404。保存包含revision，拒绝覆盖旧版本。修改记录保存时间、操作类型、操作者显示名和字段前后值；最终版本新写入记录同时保存actor_id，历史记录允许缺少用户ID。

数据库新增project_catalog，迁移m3101。已有项目首次访问目录或下载导入模板时，从当前快照复制初始目录，事务锁防止重复初始化；之后以独立档案为准。内部物资/科室ID保持稳定。

## 历史与导入规则

- 改名称/规格/编码、停用均不改已发布快照，不让已有库存消失。新名称随后续导入发布生效；旧核查继续使用旧快照。
- 物资一旦出现在任意库存快照中，基础单位锁定。另一基础单位应创建新编码；本版本不提供自动数量换算。
- CSV表头兼容M3。模板按当前档案名称/编码输出；新档案可用于导入，停用项明确阻断。已有库存中停用项不会偷偷从模板删除，应在完整文件中明确移除对应记录，或先重新启用。
- 模板携带主数据指纹。上传期间目录发生变化需重新下载；候选携带服务端指纹，发布时再次检查。目录编辑与快照发布共享项目事务锁，过期候选不可发布。
- M3旧版未发布候选缺少指纹，必须重新校验；已发布快照和导入记录保持可读。客户端遇到目录/快照冲突后提供重新载入入口。
