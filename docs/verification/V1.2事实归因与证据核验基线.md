# V1.2 事实归因与证据核验基线

日期：2026-10-05。用户回复“开始”，授权上一轮提出的四项本地交付。实际作者、实现与自检为当前 Codex；无独立 QA、业务签收或子 Agent。

## 范围和验收设计

1. 保留 2026-10-04 首例 P1 原始失败及停止轮次；离线复现缺日/旧快照混淆。
2. 从当轮实际只读工具生成原因—物资—科室账本，原因可重叠，位置数不等于物资种数，不把零消耗当数据质量错误。校验正文、建议和草稿的已知原因计数及对象表达。
3. 当轮工具同时生成可选择的原子事实目录。新真实模式输出逐段 claims：fact 必须原样使用本轮目录事实；policy 必须是本轮文档摘录中的连续原文；suggestion/unknown 明确标记尚未语义核验。正文逐段与 claims 相同，禁止目录外的自由事实段落。建议需关联本轮来源，但来源存在不代表建议语义得到证明。
4. 本地离线评测、受控完整运行与浏览器证据回查，回归后冻结；新真实模型复测仅提案，另需明确预算授权。

验收先覆盖：原始“2个缺日”错误、中文/全角计数、反向数量表达、正确分项、多原因重叠、同物资跨科室、范围外对象、正确来源错事实、错来源类型、伪造原文、缺 claims、正文旁路、草稿对象归因、一次纠正成功/持续失败、预算停止、历史答案/证据不变。数据集均为作者开发/曝光回归，非盲测。

## 共享契约变更（实施前记录）

HTTP 请求、工具参数、事件结构、数据库表不变；数据库 JSON 保存新增字段，无迁移。AnalysisView 增加可选 reason_breakdown 与 claims；历史记录缺字段时默认 null，前端沿用原正文/引用展示，不补写历史。新增模型输出 claims（kind/text/evidence_ids/fact_ids），真实模式校验必填，mock 历史流程豁免。工具返回增加服务端 fact_catalog，与当轮 evidence_id 一一对应；原始 facts 和 hash 保留原样。工具事实目录不增大授权范围，均来自实际已查询结果，不另行查询。

例：缺日1个位置/旧快照1个位置/零消耗1个位置，缺日不能表述成2个位置。fact claim 的 text 与服务器 catalog 项的 text 完全一致且引用匹配；policy text 在 document excerpt 中逐字存在。正文采用 kind 标签及 text 逐段渲染，原始模型响应始终保留在 checkpoint。

前端在现有结果详情添加原因分项和“逐条依据”折叠区，显示事实核验/原文匹配/待人工核实并可点击来源。OpenAPI 和生成类型一并更新；旧客户端可忽略新增字段。提示与核验版本更新以标明新契约；恢复中的旧运行使用旧契约并标记 legacy，不能伪装为新核验通过。

核验细化：新工具证据的 facts 在原数据之外保存 reason_breakdown 及其独立 hash，绑定同一快照 source_hash。原工具数据 hash 保持其既有语义；新增派生原因清单独立核对。只对风险、库存和消耗工具生成原因清单，批次查询不能凭内部范围数据显示未查询的数据质量原因。风险证据回查同时展示这份冻结清单，特别保留零消耗对象（它不是异常 finding）。

## 执行边界

只用生成场景与隔离临时数据库。无新付费调用，不重启日常服务、不切换日常库、不邀请外部人员、不部署、不接真实企业资料、不写库存交易、不自动确认任务。LangSmith 观测行为保持独立；本地受控评测关闭云追踪。所有旧失败文件保持原样。

## 后续真实复测提案

冻结版本后另开隔离轮次，先测原因归属（缺日/旧快照/零消耗、多原因重叠、同物资跨科室）、逐条证据与限定追问，再测既有核心场景。最多10运行，每运行20,000、全轮120,000 recorded tokens 可作为预算提案；不是硬计费上限，未获本轮付费授权。P0/P1 停止追加调用，保存所有原始结果，不续用旧轮次。必须单列格式/工程成功、语义支持度、用量/时延和独立业务评审结果。
