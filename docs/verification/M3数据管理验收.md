# M3 数据管理交付与验证边界

2026-09-28；作者/执行者：Codex。按用户批准的本地 CSV 导入闭环实施。基线见 [M3接口与验收基线](M3接口与验收基线.md)。这是实现者自检记录，不代表独立 QA、用户正式验收或上线。

## 本次交付

左侧新增“数据管理”（`/app/imports`）：最近50次导入记录、当前快照 CSV 下载、三文件上传、字段指南、业务时点、逐文件/行校验问题、库存和差异预览、人工发布确认。复用现有浅色台账布局、共享 DataTable 和按需加载。页面区分错误和警告，避免大面积蓝色提示框。

库存/批次/消耗三个固定模板构成完整替换快照。当前版本仅映射现有项目的物资业务编码与科室名称，不自动创建主数据、不做增量合并。单位必须与基础单位一致，数量最多12位整数和4位小数；单文件1MB/10000行，支持 UTF-8 BOM。

错误阻断：表头/列数、未知或歧义目录项、单位、非法数量、重复库存组合/批次编号/每日消耗、无批次、批次汇总不一致、消耗窗口外日期、无时区或未来库存记录。业务时点不能早于当前快照，统一北京时间。

警告需人工确认：库存记录超过24小时、消耗缺日、原库存组合被移除。缺日不补零，异常中心继续显示对应数据缺口。差异清单包含新增/移除及库存、批次状态/效期、每日消耗变化；仅批次变化也会标注。

后端新增 `data_imports` 审计表，迁移 `m3001`，OpenAPI `m3.0` 和生成的前端类型同步。项目 owner/demo_owner 可上传/发布；其他项目成员只读；跨项目404。上传有请求幂等键，发布基于候选记录幂等；项目事务锁串行化发布，旧预览返回409，必须重新校验。校验不改当前数据，发布插入新快照并记录发布人/时间，保留原快照、核查、证据。

## 使用与剩余范围

打开数据管理 → 新建导入 → 下载三份当前快照 CSV → 按模板整理完整数据 → 设置北京时间业务时点 → 上传三文件 → 校验并核对变更/移除清单 → 确认警告 → 发布。

仍未实现：物资/科室主数据维护页面、任意字段映射、Excel/接口直连、增量导入、发布回滚入口、团队审批、排程巡检与自动采购。先用当前已有目录完成真实文件的小范围人工验收，再决定扩展主数据与映射；不要直接宣称完整企业 SPD 系统已完善。真实公司数据、在线 PostgreSQL、多用户生产压测和云部署均未验证。
