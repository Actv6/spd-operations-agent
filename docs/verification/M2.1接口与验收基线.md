## CR-M21-001（实现前）

- 工作台从同一快照的确定性 RiskReport 选择优先异常；页头、异常列表、明细、核查表单固定同一 snapshot_set_id。刷新原子提交整组数据，忽略迟到响应；已打开的表单/明细固定打开时的快照。
- Options 增加可选 focus（general/risk_scan，默认 general）。明确“分析全部异常”动作设 risk_scan；服务器在保存前要求实际执行 compute_risks，普通历史请求兼容。
- RunView 增加可选 options 以保留重试意图；默认 general 计算幂等哈希时仍按旧请求结构规范化。OpenAPI 版本 m2.2，数据库无需迁移。
- 模型输出可增加 risk_summary（扫描数、无法估算数、数据质量/零消耗原因数、发现数）。执行 compute_risks 的新运行必须返回与确定性结果一致的计数；结构、计数或业务编码/内部字段表达不合格最多纠正一次，仍失败则显式失败，不替换成模板成功。
- Analysis 增加可选 risk_summary，服务端从真实工具结果保存，旧分析读取默认空值。前端以结构化事实显示概况。引用ID校验和这些检查不是逐句语义证明，真实样本仍独立评审。
- 模型工具内容使用精简投影，去除重复源行ID；完整证据仍保留。大范围批次/消耗先给摘要，明细要求缩小范围；超预算明确拒绝而非默默截断。添加输入字符上限和累计用量预算；字符预算不宣称精确 tokenizer 计数。
- 前端按页面及详情拆包；旧原型、API路径、共享表格、草稿确认与本人任务规则保留。

## 实现前验收设计

1. 过期高关注项进入首页，和异常中心同源、确定性排序。
2. 旧快照A读取后发布B：A报告/明细/核查固定A，统一刷新后切B；迟到响应不覆盖新状态。
3. 精简工具输出保留数值/单位/缺日/null/范围计数，审计证据完整；大范围明细明确摘要；权限不能绕过。
4. 风险计数错、物资编码错、内部字段、无风险工具：有界纠正或失败。预算失败留存usage，无自动降级。
5. 固定企业场景评测：全项目、缺日、零消耗、追问、草稿、无依据；自动规则与人工语义评审、真实DeepSeek与mock分开。
6. 后端回归、迁移、当前OpenAPI与类型一致、前端构建；关键流程API与浏览器分别留证。对比入口加载资源和总构建体积，不靠拆chunk声称首屏提速。
