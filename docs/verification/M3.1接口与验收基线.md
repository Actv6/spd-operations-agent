# M3.1 主数据管理基线

2026-09-28；用户已批准物资档案、科室目录及导入联动。实现、自检：Codex；非独立QA。沿用紧凑台账与共享DataTable。采购、回滚、任意字段映射、Excel、部署仍在范围外。

新增 /app/products、/app/departments：查询、状态筛选、新增、编辑、停用/启用。复用项目owner/demo_owner写权限，成员只读。停用不是删除，不移除已有库存和历史记录。已用于任意库存快照的物资基础单位锁定，需新建编码表达另一基础单位，避免对已有数量隐式换算。

API /api/v1/projects/{project_id}/catalog/{kind}（kind=products|departments）：GET列表（items、can_edit）；POST新增；GET /{id}详情含修改记录；PUT /{id}全字段+revision更新。编码规范化大写且项目/类型内唯一；科室名称规范化后唯一；物资可同名不同规格。PUT采用项目事务锁与revision防止覆盖并发修改，409需刷新。无需删除接口。

数据库 m3101 新增project_catalog；按项目首次访问时，从该项目当前快照复制目录并提交，项目锁避免重复初始化；后续不从快照覆盖档案。内部source_id稳定，名称/编码修改不改该标识。新注册项目同样可初始化。保留原生成数据来源元信息。

CSV表头兼容M3，物资按编码、科室按名称映射。验证采用当前启用目录并深拷贝到候选；模板使用当前目录名称与编码，基础单位以不可变的原数量口径为准。停用目录仍可在模板中看见原库存，上传时明确报停用，需从三份完整文件移除或重新启用。模板额外返回停用提示和主数据指纹；请求接受可选catalog_hash，UI携带以检测上传期间目录变更。候选记录含目录指纹；发布与档案修改共用项目事务锁，指纹变化阻止发布并要求重新校验。M3旧待发布候选缺指纹需重校验；已发布快照完全保留。
