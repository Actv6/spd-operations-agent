# 数据管理导入优化与验收

2026-09-28；实现及自检Codex，没有独立QA。用户同意使用独立Playwright浏览器验收（页面控制工具连续两次连接超时）。全部浏览器数据写入临时SQLite库，非当前项目；未调用模型。

## 已完成

- 复用既有台账视觉，上传抽屉使用三张文件卡片、字段规则折叠、业务时点与固定底部操作区。
- `CsvFileUpload`负责选择/拖拽、文件名/大小、进度、替换、移除/取消、独立错误；`csvFile.ts`负责文件约束和256KiB分块UTF-8增量读取。取消、替换与卸载通过AbortController阻断旧结果。
- 上传组件通过明确回调向业务页提供CSV内容与读取状态。业务页仍负责模板、校验、幂等请求、预览及手动发布。
- 上限提高到每文件10MiB，服务端按UTF-8字节检查；保留每文件10000数据行限制，路径和JSON形状不变，更新OpenAPI，生成类型检查通过。
- 校验期间显示真实等待状态；读取期间不能提交。不使用虚构网络进度。
- 返回重新上传清空文件，防止不可见的旧内容被提交。390px抽屉宽度限制到视口，步骤条保持紧凑横排；移动导航在自身区域滚动，避免整页横向溢出。

## 实际流程证据

浏览器从页面下载库存、批次、消耗三个模板，填写库存在库量+10、对应批次在库量+10、首条消耗+1，保留原编码与表头。生成大文件时将每条原批次均分为125个唯一批次（数量精确相加、单位/状态/效期不变），共9000条、1293725字节，真实上传并经真实本地API校验。

最终预览：24个库存组合、0错误、2警告。原生成场景中一项库存记录超过24小时、一项消耗仅12/14天，警告保持，未补造缺日数据。预览前后当前快照ID一致。无JavaScript页面错误。保留填写CSV、原始预览响应及截图。

浏览器另验证：错误扩展名、超过10MiB、非法UTF-8、读取期间按钮禁用、取消读取后旧结果不会回填、重新上传清空、桌面1440×960与手机390×844。取消观察仅将本地Blob读取延迟50ms，未伪造API响应。途中发现并修复导航横向溢出与抽屉固定宽度导致的裁切；原失败日志保留。首次大批次夹具仅1028800字节未跨越1MiB，增至9000条后复测通过，此失败是夹具断言而非接口失败。
