# M3.2 数据版本管理交付记录

2026-09-28；作者/实施/自检：Codex；没有独立 QA 或多人签字。契约先行记录于 [M3.2基线](M3.2接口与验收基线.md)。用户已批准本轮。

## 已交付

- 新菜单“数据版本” `/app/versions`，共享紧凑 DataTable、日期包含年份并统一北京时间；历史缺失创建时间显示“未记录”。支持查看业务时点、发布人、库存组合数、导入校验摘要及当前版本。
- 任意两版本比较，默认当前→上一历史版本。统计新增、移除、变化、未变；列出可用库存、日均消耗，以及档案、在库/冻结/预留、批次状态/效期、每日消耗变化。按各自时点的前14天计算，缺失不补零。批次效期明细最多显示10条并说明剩余数量。
- 项目负责人可预览差异、填写至少5字原因、勾选确认，再回退。记录操作者、时间、前后版本、原因与递增revision；网络重试使用同一请求键。只读成员只能查询比较。
- 切换引用不可变快照，不改快照业务时间，不回退主数据，不覆盖 Agent/证据/个人任务。回退前尚未初始化主数据的项目先从原当前版本建立目录，防止目录被历史名称重置。
- 导入发布与回退共用项目事务锁；revision阻止并发覆盖、A→B→A后的旧模板/候选复活；缺少revision的历史未发布候选必须重校验。已发布导入重放不会重新切换当前版本。
- 场景发布CLI在新增快照时登记切换，保留无重复发布行为。既有版本在列表可查看；升级前没有切换日志的操作不伪造补录。

## 实际验证

1. 后端完整回归 **158 passed / 21.39s**（原140 + 本轮18），[JUnit](m32-version-tests.xml)。包括较早业务时点回退、原快照/运行保留、回退后导入、同请求幂等/并发、权限/跨项目、发布与回退竞争、ABA失效、旧候选、数量/效期/消耗/增删比较、目录初始化保护。
2. 完整回归包含空库 Alembic upgrade/head、模型差异检查与 PostgreSQL 离线 SQL 编译；本机 SQLite 已迁移至 `m3201`。没有运行真实 PostgreSQL 服务。
3. 前端 TypeScript、生成API类型一致性、既有14项UI/打包测试通过；Vite生产构建和Sites产物准备通过。仅构建，未发布。
4. 浏览器真实本地链路：M1浏览器测试项目查看4个历史版本，预览71f9797c→98b31c3f，原因/勾选前按钮禁用，确认回退后当前版本切换；再以98b31c3f为基准恢复71f9797c。两条操作记录可见。另比较d54aa09a，显示24项档案差异和具体科室名称变化。390×844下选择器、差异抽屉、回退表单可用，表格横向滚动；已恢复默认桌面尺寸。
5. 与迁移前本地备份逐表比较：**7快照、22运行、135证据、17分析、1个人任务、56档案全部相同**。只增加测试项目两条切换记录，最终仍使用测试前的71f9797c版本。详情 [database-check.json](m32-versions-ui/database-check.json)。未修改Ac项目业务数据。

截图与浏览器验证说明见 [UI证据](m32-versions-ui/README.md)。本地服务入口 `http://127.0.0.1:4180/app/versions`。

## 证据边界

本轮是本地功能实现、自动回归与浏览器验证，不代表完整SPD平台或企业上线验收。未调用付费模型，未接入真实公司文件；既有场景资料保持来源元数据。未验收真实PostgreSQL、向量检索、云部署；Excel字段映射、采购结算、协同审批仍未开发。

候选快照与任务证据保持原业务时点：恢复旧版本后，新核查依据也是该历史时点，不能据此声称现实库存已经恢复或异常已经解决。
