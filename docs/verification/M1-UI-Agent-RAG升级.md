# M1 UI / Agent / RAG 升级交接

2026-09-27 用户批准：Ant Design 后台改造、调用 UI Skills、修复真实 Agent、生成企业资料并导入 RAG。不是新增审批/采购平台，不云部署。

## 实现前契约与测试基线 CR-M1-005

- InventoryItem 兼容新增 department_name；快照 facts 可包含 departments，旧快照继续可读。
- 新增只读 GET /projects/{project_id}/knowledge/documents 和 /knowledge/documents/{document_id}，返回项目内版本目录、状态、生效时间、片段数、hash，详情提供原文；不得跨项目访问。
- Dashboard.stats 新增 active_documents / knowledge_chunks，原 documents 保留全部版本计数语义。
- Agent 工具名、字段、权限不变。InventoryArgs 补充 ID 语义；模型初始化提供由已授权快照构成的 scoped_inventory_catalog（内部 ID、业务编码、名称与科室），不接收前端声明的任意权限，不用宽松匹配掩盖越界。
- RAG 导入新增独立版本企业资料；旧资料/引用不覆盖。实际模式仍 lexical，不新增虚构向量。知识库展示目录和可检索内容，前端通过 API 调用现有 LangGraph worker。

验收先行：1) 中文名称/业务码/全部物资问题使用授权 ID；2) 跨项目、越权工具、撤权、无依据仍阻断；3) 新资料可重复导入、hash 校验、有效版本/ACL 筛选；4) 物资筛选/排序/分页/行内发起核查/详情；5) 新建→等待→回答→引用原文、失败/取消/重复请求；6) 至少库存+制度、缺日、无依据三类真实模型小样本，单列使用量，不声称广泛成功率；7) 桌面与窄屏浏览器、类型/构建/自动测试。

## UI Skills 工作简报

来源：UI Skills root → interface-design（https://www.ui-skills.com/skills/dammyjay93/interface-design）。本地未预装该技能，已读取目录的完整技能正文。Product Design get-context 用于确认现有后台和已批准方向，不新建营销站/脚手架。

使用者：医院 SPD 驻点专员，上午盘点后找到需核查物资，查证据、向项目经理交接；目标是快速找到一行并核查，不是观看运行队列。

领域：科室、可用库存、基础单位、14 日消耗、覆盖基线、冻结批次、供应交期、有效制度、证据链。
色彩世界：库房标签白、台账纸灰、正文墨黑、流程蓝、核验绿、待核查琥珀；页面白/冷灰，单一蓝主操作，绿色/琥珀仅表状态。
特征：每个物资入口连接“库存事实—制度依据—AI 核查”，结果紧邻可回查证据，业务时间一直可见。
拒绝：空队列大看板→状态标签页列表；三行高物资卡→紧凑表格+详情；常驻窄侧栏→按需宽抽屉。

## 实施与验证结果（2026-09-28）

实际实施者及验证执行者：Codex 当前任务。同一执行者的自动测试与浏览器核验，不是独立 QA 签收或多人评审；用户明确只需接入业务 Agent，本轮没有调用开发子 Agent。

### 本地实现

- Ant Design 6.6.5 替换正式入口的手写控件；浅色侧栏、工作台概览、紧凑库存表、核查状态列表、按需结果/证据抽屉。使用真实 API 返回的统计，不造趋势。
- UI Skills CLI 实际执行 categories、list --category systems、get dammyjay93/interface-design；该技能具体影响层级、语义配色、4px 间距、表格密度、数字对齐和桌面/窄屏验收。没有全局安装技能，也没有把“使用技能”说成自动设计评分通过。
- InventoryPanel：物资名称/业务编码/规格搜索、科室/数据质量/低覆盖筛选、数值排序、10/20/50 分页、完整物资详情与行内核查。
- KnowledgePanel：有效/历史版本目录、名称过滤、原文阅读、词法检索、从问题进入 Agent。答案使用 Markdown（支持表格），引用可回查原文、版本、Hash 和字符位置。
- Agent 仍为只读 LangGraph 工具调用；服务器把本次授权物资的名称、编码、内部 ID 对照提供给模型，空筛选仍严格限制在请求范围。未放宽工具白名单和权限。
- 修正最终生成阶段：显式要求 ModelAnswer JSON Schema，后端继续严格校验，不从散乱文本里“猜”出成功，不回退模板；最终返回的用量在校验失败时也落库。
