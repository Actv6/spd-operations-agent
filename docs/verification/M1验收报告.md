## 实现范围

- 身份：Argon2id 密码哈希，HttpOnly 会话 Cookie，服务端过期/注销；签名 CSRF Cookie + 请求 token + Origin 校验；数据库登录/注册限流；生产 Secure 配置独立。
- 隔离：注册事务新建组织、项目与 demo_owner 成员；项目、run、analysis、evidence、知识请求校验服务端成员；无权资源统一 404；worker 执行与外部生成步骤再查权限。
- 数据：原始合成库存/批次/消耗实际存入不可变快照 JSON，SQLAlchemy 持久；查询用 Decimal 计算，API 数量为字符串。清洗液 120/20=6；反应杯 12/14 天记录，日均和覆盖返回 null；旧快照暂停覆盖估计。完整库存写入与逐日风险模拟不在本轮。
- Agent：LangGraph 有界 model→tools→model→finalize；仅 get_inventory/search_knowledge；服务端绑定项目与快照，Pydantic 拒绝额外/越界工具参数。mock/model 可辨，未启用自动 rules_only 回退。
- 队列：数据库 CAS 领取、90 秒租约、最多 2 次、fencing；事件游标、工具来源、应用级图 checkpoint、分析结果持久；run_id 唯一分析结果；取消后拒绝迟到提交。处理中已发出的供应商请求不承诺即时停止计费。
- RAG：导入现有 Markdown 和 manifest；源 hash、版本、生效区间、project、synthetic；章节/字符偏移分块；中文双字词元与 BM25 风格评分；授权/有效版本先过滤，重叠生效版本报冲突；引用可回查，历史失效标记。
- UI：保留第三种深蓝侧栏、三列工作区和右侧详情；增加登录注册、数据库看板、库存、知识搜索、异步事件、回答、引用和历史失败；旧原型仍位于 `/prototype`，其 localStorage 任务不冒充新后端数据。

## 自动检查细节

先写 `M1接口与测试基线.md`，再实现后端。独立 API/worker/RAG 的首轮 24 项测试通过后才接入前端问答；最终扩展为 32 项。

| 用例组 | 数量 | 核心覆盖 |
|---|---:|---|
| auth/data | 5 | 注册重复账号、哈希、会话失效/退出、CSRF/Origin、错误密码、限流、双用户隔离、库存和缺日 |
| knowledge | 2 | 重复导入、医院 B 不入库、旧/未来/过期版本、章节偏移、空命中、重叠版本冲突 |
| agent | 12 | 独立运行、幂等、事件游标、结果重读、跨用户拒绝、缺 key、并发领取、fencing、取消/撤权、7 类故障参数化、无依据与严格请求 |
| provider | 5 | 请求形状、thinking disabled、JSON Output、usage 映射、去除推理字段、429/401/503、网络超时 |
| recovery/migrations | 8 | 工具后进程死亡并恢复、无重复证据、重试耗尽、取消后迟到结果、历史撤销引用、空/截断响应、空 SQLite 库迁移/无漂移、PostgreSQL 离线 SQL |

上表 agent 组的 12 项包含参数化计数，精确节点列表与总数以 XML 为准；不是 32 个真实模型案例，也不是蓝图计划的 120 个保留集案例。

复现：

```sh
cd backend
.venv/bin/pytest -q --junitxml=../docs/verification/m1-backend-tests.xml
.venv/bin/alembic check
.venv/bin/python -m app.cli openapi ../docs/verification/m1-openapi.json
cd ../frontend
pnpm types:api
pnpm check:api
pnpm typecheck
pnpm build
pnpm test:sites
```

## 浏览器执行记录

测试浏览器：Codex 内置真实浏览器。地址 `http://127.0.0.1:4180`，API `127.0.0.1:8010`，单独 worker 进程。测试账号为本地合成身份 `m1-browser@example.test`，密码未写入本报告；用户可另行注册本人演示账号。

1. 匿名访问重定向 `/login`；注册新账号直接进入本人项目，看板显示数据库物资 24、待核查 2、知识版本 5。
2. 提交清洗液核查，实际 POST 202 建 run，worker 完成，前端轮询 7 条事件，自动显示 mock 回答、120 瓶、20 瓶/天、6 天及 5 条引用。
3. 点补货制度引用，原文为第 2 节缺货核查；字符偏移 59–164，源 hash `34bfa69fd0ef879c7a908673ab3c9235cc63dacaf9cfe9de2a7ad8e3c4516c34`，与现有合成文件一致。
4. 浏览器刷新与 API/worker 重启后，会话和历史结果仍可读取；点历史卡片能回查原引用。
5. 停止后端再刷新，显示“服务暂不可用”，不展示伪数据库成功；恢复后点击重连重新进入。
6. 临时把 API 设为 deepseek 且无 key，运行 `d364f3bf-e627-456e-9c8b-179c8e8ad6f8` failed，显示 `PROVIDER_NOT_CONFIGURED`，无 analysis；之后恢复 mock。
7. 知识页搜索“补货核查”实际命中有效 v1.0；搜索“量子宇宙星际飞船”返回无依据提示。
8. 退出后访问 `/app` 回到 `/login`；错误密码显示拒绝；正确密码重新登录，库存和历史仍在。

## 发现与修复

- 首轮测试误把缺日夹具写成 P002，依据原始 gold_cases/model 核对后更正为 P006；未改变原始数据迁就测试。
- 浏览器发现终态清理轮询导致回答未自动显示：改为先读取 analysis，再转终态；清洗液与反应杯的新运行均回归自动显示。
- 窄屏沿用了旧原型 body 360px 最小宽度：M1 覆盖为 320px，实测 scrollWidth 与 clientWidth 相等。
- 状态初始化不再短暂显示 DeepSeek，改为读取配置；真实模式缺 key 现在能显示配置未就绪。
- SQLite 相对路径固定以 backend 目录解析，避免从项目根运行脚本意外连接另一数据库。

本轮已执行用例未发现尚未处理的核心流程故障；这不是安全审计、真实模型质量或企业试点适用性保证。
