# M3 数据导入与快照发布基线

2026-09-28；实现与自检：Codex。用户“开始”授权本地数据管理闭环，覆盖此前 M2/M2.1 对数据导入的排除；不扩大至采购、库存事务写回、团队协作或部署。

范围：固定模板的 UTF-8 CSV（库存、批次、近14日消耗），复用当前项目物资/科室目录；整份替换快照，不做增量合并。以业务编码和科室名称映射，未知或歧义映射阻断。每文件最多1MB、10000行。校验生成不可变候选；有错误不得发布，有警告需人工勾选确认。缺日不补零。删除原有物资科室组合须显式展示并警告。发布后旧快照、Agent结果和引用不变。

契约（新增 /api/v1/projects/{project_id}/imports）：GET 列表及 can_publish；POST 校验创建（Idempotency-Key，base_snapshot_id、as_of、三个 CSV 字符串）；GET /{id} 预览；POST /{id}/publish（acknowledge_warnings）。GET /import-template 返回当前快照的三份 CSV 和业务时点，页面提供下载及字段说明。仅 owner/demo_owner 可上传与发布，项目成员可读；跨项目404，非发布角色403。上传不调用模型。

发布事务：锁定项目行，重新读取候选和当前快照；重复发布返回同一结果；基准快照发生变化返回409，需重新校验；拒绝早于当前快照的业务时点；统一北京时间带时区 ISO 格式。插入新快照、候选发布状态/发布人/时间一起提交。没有修改既有快照的接口。

验证先行：CSV BOM/空文件/错误表头/重复行/未知编码/单位不符/非法数值/日期/批次汇总；缺日及旧记录警告；无权限和跨项目；校验不改变当前快照；发布幂等与竞争发布；原核查与证据快照保持；新风险读取新快照；迁移、契约生成、前端构建及本地浏览器操作。真实公司文件、PostgreSQL在线并发、云部署均不在本轮验证证据中。
