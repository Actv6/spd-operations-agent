# 人工复核操作说明

2026-10-05。本轮为本地功能交付，下面是使用步骤，不是业务人员已签收的证明。

## 核查人员怎么用

1. 在“核查工作台”的核查记录中查看“人工复核”列。可用筛选框找“需要复核 / 处理”“发现错误 / 有争议”或待人工复核记录。这里只覆盖最近200条核查记录，不是全量待办队列。
2. 打开核查详情，分别看AI运行状态与人工复核状态。展开“人工核对库存、批次与消耗”，核对记录的业务时间、缺失天、数量、冻结/预留以及有效资料。来源只是已保存记录；账实一致性和资料适用性仍须人核实。
3. 在人工复核里选择状态，填写人工结论、核查依据与核对过程。发现错误或资料不足时，必须说明下一步。可关联本次保存依据，外部台账/实际核实信息写入依据说明；本轮不支持附件上传，也不会替你验证外部材料真实性。
4. 出现纠错反馈时，在人工结论中逐条回应，再勾选全部已处理反馈。填写处理记录不等于问题自动解决；若仍有争议，保存为“发现错误 / 有争议”或“资料不足”。只有复核人实际核实后，才能选择“人工确认”。
5. 点击“保存人工复核”。系统记录账号、姓名、时间、数据版本和原分析hash；本人提交显示“本人自查”，其他有权限账号显示“其他账号复核”。后者不是资质认证，也不等于独立业务人员已签收。
6. 高关注、数据质量异常、AI依据不足、旧质量契约记录及业务待办需要先复核。待办确认也检查原核查和所有会话祖先；在会话按钮中切换到被提示的原核查，逐一处理。完成复核后刷新草稿状态，再编辑并确认内部待办。
7. 原始数据或制度有误时，使用现有数据管理/资料库维护功能，经人工核对后发布新版本，再“查看当前库存并重新核查”。新核查需由用户明确发起，可能使用模型；本轮验收没有发出真实模型调用。旧答案、旧来源与人工复核记录保留。

AI失败或取消时，仍可查看绑定库存和已经保存的依据，直接记录人工核查结论。人工记录不会把失败的AI运行改成成功，也不依赖AI先生成一个回答。

## 状态怎么理解

| 页面状态 | 含义与处理 |
|---|---|
| 待人工复核 | 尚未确认，或已确认记录的来源发生变化；查看原因与来源提示 |
| 人工确认 | 有复核人记录结论与依据，针对绑定版本；不表示业务审批或风险解除 |
| 发现错误 / 有争议 | 人工指出问题，或新增纠错反馈待处理；暂停确认相关新待办 |
| 资料不足 | 需要补查信息，暂停确认相关新待办 |

普通结果也保持待人工复核，可主动抽查，包括“没有命中风险”的结果。本轮没有制定并执行企业抽样制度，也没有后台随机抽样、自动分配或提醒。

已有任务不会因后续纠错被自动取消或改写；任务详情和原核查会显示需要再次复核，处理人核实后记录措施。任务完成不会改写库存、取消异常或自动关闭人工争议。

## 复核权限与责任

现有项目 owner/demo_owner 账号可以提交，已有项目成员可以读取；所有身份由服务端确定。本轮没有新增邀请、多人审批平台或角色管理入口。需要其他人员复核时，须先有合法项目权限；本轮只在隔离验收库中配置测试账号验证权限，没有邀请任何真实人员。

试用前应指定实际核查人，关键业务结论由熟悉该业务的人员复核。独立验收人员应自行准备案例和预期，再检查AI与人工处理流程；开发者自动化测试与其他测试账号不能代替这种验收。
