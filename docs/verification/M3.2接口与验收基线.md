# M3.2 数据版本与手动回退

2026-09-28 用户批准；设计、实现、自检：Codex，未安排独立 QA。沿用紧凑台账，新增 /app/versions。范围为版本历史、任意两个版本差异、人工回退与操作留痕；不含采购、Excel、定时任务、部署或主数据目录回退。

快照事实及业务时点不可变。新增 snapshot_activations 追加式切换记录，项目内 revision 单调递增；当前数据取最后切换指向的快照，无切换记录时兼容原最新快照。历史列表包含已有快照及 CSV 校验摘要，旧资料明确标为历史版本（无导入校验记录）。发布与回退共享项目事务锁，切换记录同时提交。场景发布 CLI 同步登记切换。

GET /api/v1/projects/{project_id}/versions 返回版本列表、当前快照、revision、写权限与切换记录。GET /versions/compare?from_id=&to_id= 返回两侧业务时间、库存组合新增/移除、库存数量/消耗/效期/档案差异。仅允许同项目快照，数据按各自业务时点计算，不把旧数据冒充当前采集。

POST /versions/restore 请求 target_snapshot_id、expected_revision、reason（去空白后 5–500 字）；Idempotency-Key 必填。owner/demo_owner 可切换。必须预览后在 UI 填原因确认；服务端检查项目归属、当前版本、revision 与幂等哈希。切换到当前数据返回409，重复请求返回同一切换记录，冲突请求409。并发发布/回退只允许匹配预期版本的操作成功。

import-template 增加 publication_revision，导入请求接受该字段；候选保存服务端 revision。校验与发布检测 revision，阻断 A→B→A 后旧预览复活。旧未发布候选缺 revision 时要求重校验，已发布请求仍可重放。UI 收到 SNAPSHOT_CHANGED 清除旧模板。历史 Agent、证据、任务继续绑定原快照；回退不代表解决异常，不自动更改目录。

先行验收：无历史初始化、发布记录、较早业务时点回退、差异（冻结/预留/消耗逐日/批次效期/增删/不同时间窗）、原因必填、只读角色、跨项目、幂等重放/冲突、并发回退/发布、ABA 预览失效、回退后继续导入、历史事实/引用保持。回归所有后端测试、迁移和 PostgreSQL 离线 SQL、API 类型、前端构建；浏览器验证页面、差异、人工回退、历史记录、窄屏。不调用付费模型。
