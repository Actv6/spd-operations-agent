# 密钥配置与数据库查看

## DeepSeek 密钥

编辑项目中的 `backend/.env`，不要改成前端变量，也不要将密钥提交或发到聊天里。

```dotenv
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=填入你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

模型名称须以你的账号实际可用型号为准。保存后停止当前启动脚本（Ctrl+C），在项目根重新执行 `backend/.venv/bin/python scripts/start_m1.py`，让 API 和 worker 同时载入配置。仅配置成功不代表模型调用已经验证；缺密钥时库存/知识查询可用，AI 核查按钮停用。

## 当前数据库

当前使用本地 SQLite，文件是 `backend/var/spd.db`，不是 PostgreSQL。前端库存、知识和核查结果通过 API 从此数据库读取，并非 localStorage。

在项目根的终端运行：

```sh
# 只显示业务表的记录数，不读取密码和会话令牌
cd backend
.venv/bin/python -m app.cli db-summary
```

也可用 SQLite 客户端，以只读模式打开 `backend/var/spd.db`。如果系统已有 sqlite3，在项目根运行：

```sh
sqlite3 -readonly backend/var/spd.db
.tables
.headers on
.mode column
SELECT id, name FROM projects;
SELECT id, as_of, source_hash FROM snapshots;
SELECT title, version, status FROM documents;
SELECT id, provider, status, created_at FROM agent_runs;
.quit
```

| 数据表 | 内容 |
| --- | --- |
| users / organizations / projects / memberships | 用户、组织、项目和授权；users 仅存密码哈希 |
| snapshots | 不可变库存快照，facts JSON 内含产品、批次、14 天消耗与汇总 |
| documents / chunks | 文档版本、正文、章节片段、hash 和生效状态 |
| agent_runs / run_events | AI 请求、状态、失败原因和过程事件 |
| analyses / evidence | 核查结果与原文证据 |

旧版本会保留，文档旧状态不会继续参与当前检索。请勿直接编辑数据库数量或历史证据，避免破坏来源关系。备份运行中的 SQLite 应使用 SQLite backup 接口；不要仅复制 `.db` 而丢失 WAL 文件。

业务场景数据是用户授权生成，并非实际企业采集；数据库读写、权限校验、确定性计算和词法检索均真实执行。三条真实模型小样本的结果与限制另见升级报告。业务后台的“库存数据”和“知识库”页可直接查阅当前数据；原始关系表仍使用上述只读客户端方式查看。
