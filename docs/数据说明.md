# 数据说明与计算口径

版本 0.1；基准时间 2026-09-27 09:00 +08:00。所有业务值均为合成值，不来自公司内部。

## 模型与字段

| 文件 | 主要字段 | 口径 |
| --- | --- | --- |
| hospitals / departments | id、hospital_id | 每条业务记录归属一个医院项目与科室 |
| products | id、base_unit、units_per_purchase_pack | 产品编码独立于名称；包装换算为演示假设 |
| inventory_batches | expiry_date、on_hand_base、frozen_base、reserved_base、status | 批次总量包含冻结量；冻结与预留不重叠；过期冻结不可用 |
| inventory_snapshots | batch_ids、available_base、snapshot_at | 同一产品/科室的批次汇总；实际系统应有导入版本 |
| consumption_daily | date、quantity_base、record_type | 有记录且为0才表示观察到零消耗；缺记录表示未知 |
| purchase_orders | ordered/received/cancelled/outstanding_base、expected_arrival_date | outstanding = ordered - received - cancelled；在途不等于当下可用 |
| knowledge_manifest | version、status、effective_from/until、allowed_hospitals、sha256 | 检索前实施项目、版本、生效时间过滤 |

本轮 JSON 用于后续后端种子数据、工具测试和场景演示。CSV/XLSX 业务导入模板将在确认字段后另做，避免把模拟格式误认为企业原始格式。

## 计算边界

1. 日均消耗：近14个完整自然日之和除以14；有缺日时不计算正式预测，提示缺失。
2. 覆盖天数：可用库存 / 日均消耗；日均为0时返回未知/不可估计，不返回无穷大或“肯定充足”。
3. 简单覆盖天数是解释用基线。正式缺货分析还应逐日模拟确认在途、到货日、冻结及到期退出，不能只比较“库存天数 < 交期”。
4. 临期按每个批次识别；30天是演示阈值，不是法定统一标准。先到期先消耗的估计也不能自动授权临床使用、调拨或退货。
5. 到期日当天能否使用要服从产品说明和公司规则。数据夹具约定 expiry_date 为演示最后可用日；G03 仅断言“接下来10天消耗后的数量”，不是精确报废量预测。
6. 快照超24小时的拦截阈值、交期和包装均是模拟配置。医院A的一条快照故意滞后72小时，用于验证不同时间来源不能混算。
7. 试剂开封后稳定期、上机有效期、温控记录等没有完整建模；此版本只支持未开封库存的批次日期演示，不能声称覆盖试剂全生命周期。

## 需要业务人员最终确认

消耗与配送/申领区别；冻结、预留及可用量口径；包装转换与退库；批次/开封效期；交期统计；同项目调拨权限；真实SOP及审批人；数据同步频率；可接受误报和漏报。

## 验证边界

校验脚本验证主外键、批次汇总、可用量、计量单位、历史日期、订单余量和预设数值案例。它不实现业务应用，也不证明 RAG 召回、模型回答、后台权限、浏览器交互或真实服务器性能。
